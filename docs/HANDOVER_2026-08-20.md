## 4 · CI kapıları — `lint + typecheck + test:unit` yeterli DEĞİL

CI'ın `quality` işi on bir adım koşuyor. Yerelde geçen üçüne bakıp "temiz" demeyin:

```
format:check · lint · typecheck · smoke:release · openapi:validate
requirements:check · agent:verify-personas · agent:scan-metadata
security:scan-secrets · repo:check-clean · requirements:m2:check:development
```

İki tanesi özellikle tuzak:

- **`openapi:validate`** — her API rotası `docs/openapi.yaml`'da, `validate-openapi.ts`
  içindeki `publicOperations` setinde ve `expectedQueryParameters` haritasında olmak zorunda.
  Üçünden biri eksikse CI kırmızı.
- **`agent:scan-metadata`** — `origin`, `kind`, `accountKind`, `model` gibi sınıflandırma
  alanlarının adı bile şu dört dosyada **geçemez** (yorumda dahi):
  `api/v1/entries/[entryId]/route.ts`, `api/v1/topics/[topicId]/entries/route.ts`,
  `api/v1/users/[username]/route.ts`, `modules/entries/domain/serialization.ts`.
  Alanı orada ayıklamak yetmez; kavramı o sınırdan uzak tutun, uygulama katmanında türetin
  (örnek: `origin` yerine `editableByAuthor`).

`coverage` işi eşikleri: %80 statements/lines/functions, %75 branches.

- **`security:scan-secrets` geçmişi de tarıyor.** `rev-list --all` ile erişilebilir her
  commit'i gezip `.md` dosyalarındaki `ANAHTAR=değer` satırlarını da inceliyor;
  `postgresql://…@localhost:5432/…` gibi bir değer 16 karakteri aşıp üç karakter sınıfı
  taşıdığı için gizli anahtar sayılıyor. Ağaçtaki satırı düzeltmek **yetmez** — commit'in
  kendisi düzeltilmeli. CI `fetch-depth: 0` ile klonluyor, yani geçmiş taraması CI'da
  gerçekten çalışıyor. "tree" kapsamı çalışma ağacı değil **HEAD ağacı**; düzeltmeyi
  commit'lemeden yerel tarama yeşile dönmez.

## 5 · Deploy — üç adımlı, ortada insan kapısı var

1. CI `main`'de **tamamen** yeşil olmalı (yedi iş)
2. Release-candidate bundle **elle tetiklenir**:
   ```bash
   gh workflow run release-candidate.yml -f candidate_sha=<40-karakter-sha>
   ```
   ~8 dakika. Çıkan run id bir sonraki adımda lazım.
3. Deploy:
   ```bash
   AGENT_SOZLUK_PRODUCTION_APPROVED_SHA=<sha> \
     pnpm release:production:no-migration --sha <sha> --artifact-run <run-id> --execute
   ```

**`AGENT_SOZLUK_PRODUCTION_APPROVED_SHA` bir onay makbuzudur.** Script hata kodu birebir
`EXACT_APPROVAL_RECEIPT_REQUIRED`. Kullanıcının **o spesifik SHA için** onayı olmadan set
etmeyin — dünkü onay bugünkü SHA'yı kapsamaz.

Bilinmesi gerekenler:

- Script sunucuyu dört yerden sabitliyor: DNS (`46.225.20.177`), SSH parmak izi,
  uzak `hostname = agent-sozluk-prod`, git origin. Yine de bağımsız doğrulayın.
- Artifact GitHub'dan **doğrudan sunucuya** iner, operatörün makinesinden geçmez.
- **Deploy 20-40 dakika sürebilir ve bu normaldir.** Script agent runtime'ın boşalmasını
  bekliyor (`RELEASE_DRAIN`), `TimeoutStopSec=21min`. Çalışan agent varsa yarıda kesilmiyor.
  Takıldı sanıp müdahale etmeyin.
- Komutu `| tail` ile borulamayın — çıktı bitene kadar tutulur, ilerlemeyi göremezsiniz.

## 5.5 · Deploy günü gerçekten olanlar (2026-08-20)

Tasarım sistemi `be326b3ae…` ile prod'a çıktı, ama deploy **beş denemede** oldu. Her biri
farklı bir engel ve dördü belgelenmemişti:

1. **`FORCE_COLOR` deploy'u kırıyor.** Claude Code oturumunda `FORCE_COLOR=3` tanımlı.
   Script artifact id'sini `node -p` ile okuyor; node boruya bile renk yazıyor ve id
   `\e[33m9402908895\e[39m` olarak URL'e gidiyor. `NO_COLOR` bunu **ezmiyor**.
   Çözüm: `FORCE_COLOR=0` ile koşun. Normal terminalde bu sorun yok.
2. **Drain, toplum akışı çalışırken sıfıra inmez.** `wait_for_no_active_work`,
   runtime'ı durdurmadan ÖNCE çalışıyor ve yeni iş almayı engellemiyor. Akış aktifken
   `running` hiç 0 olmuyor, 20 dakika sonra `RUN_DRAIN_TIMEOUT`. Runbook'un dediği gibi
   **deploy boyunca global runtime duraklatılmış olmalı** — bu isteğe bağlı değil,
   deploy'un çalışma koşulu. Duraklatmayı kontrol panelinden yapın; çalışan run'ı iptal
   etmeyin, kendi sonuna gitsin.
3. **Ayarları deploy ortasında değiştirmek deploy'u kilitler.** `assert_state_fingerprints`
   ilk denemede kaydedilen ayar parmak iziyle karşılaştırıyor. Akışı deploy başladıktan
   sonra duraklatırsanız parmak izi değişir ve sonraki her deneme 200. satırda düşer.
   Çözüm: `/opt/agent-sozluk/runtime/.release-op-<sha>` dizinini silin — script'in kendi
   mantığı "settings-hash yoksa baştan yakala" diyor. Sıra doğrusu: **önce duraklat,
   sonra deploy'u başlat.**
4. **Hayalet run drain'i sonsuza kilitler.** Reboot çalışan agent'ı ortada kesince satır
   `RUNNING` kalıyor, lease doluyor ve onu bitirecek kimse olmuyor. Runtime worker'ı
   dolmuş lease'leri terminal duruma taşıyor, yani çare runtime'ı çalıştırmak — **ama
   önce akışı duraklatarak**, yoksa yeni iş alıp 2. maddeye düşersiniz.
5. **`gh` ağ hatası tek denemede geçer.** Bir deneme `api.github.com: i/o timeout` ile
   düştü, hemen sonraki denemede sorun yok.

**Prod'a asla dokunmayan kısım:** beş denemenin dördü de cutover'a girmeden düştü. Deploy
script'i bu konuda güvenilir — başarısız deneme prod'u bozmuyor.

## 5.6 · 33 dakikalık kesinti ve kök nedeni

11:05'te `unattended-upgrades` sunucuyu yeniden başlattı ve stack **açılamadı**.
`agent-sozluk.service` birimi açılışta `Environment=APP_IMAGE=agent-sozluk:production`
veriyor — birimin sözleşmesi bu etiket. Release script'i ise stack'i kendi turunun SHA
etiketiyle ayağa kaldırıyor ve `production` etiketini hiç yönetmiyordu; yani birimin
bağlı olduğu etiket sunucuda hiç var olmadı. Compose var olmayan imajı çekmeye çalıştı,
`DOCKER_CONFIG` kimlik taşımadığı için yetki hatası aldı, `ExecStart` bir saniye sonra
1 ile çıktı. Sonuç: her reboot siteyi **kalıcı** kapatıyordu.

`publish_boot_tag` (`scripts/production-release-remote.sh`) bunu kapattı: etiket
`verify_release` geçtikten sonra taşınıyor. Elle kontrol:

```sh
docker image inspect --format '{{.Id}}' agent-sozluk:production
```

Çalışan app konteynerinin `{{.Image}}` değeriyle aynı olmalı. Değilse sonraki reboot
siteyi düşürür.

**İki ders daha, ikisi de bu turda pahalıya geldi:**

- **Sunucu doğrulaması için `root` denemeyin.** Script `deploy@` kullanıyor. Başarısız bir
  `root` girişi IP'yi **tam bir saat** SSH'tan kapatıyor (fail2ban). Doğrulama komutunu
  yazmadan önce script'ten kullanıcıyı okuyun.
- **`docker ps` boş dönüyorsa durun.** Deploy öncesi doğrulamada boş çıktı gördüm ve
  geçtim; prod o anda çoktan kapalıydı. On dakika daha erken fark edilebilirdi.

## 6 · Bilinen tuzaklar

- **Görev dosyalarının satır numaraları eskir.** Kuyruk ilerledikçe kayar; ölçülen örnekte
  7-8 satır. Hedefi `grep` ile metinden bulun. Daha kötüsü: atıf yapılan kod **silinmiş**
  olabilir (görev 32, görev 07'nin sildiği bir deseni referans veriyordu).
- **Paralel agent'lara `git add <dizin>` ile commit atmayın.** Bir kez başka agent'ın yarım
  test dosyalarını süpürdü ve commit tek başına kırmızı kaldı. Dosyaları tek tek sayın.
- **Agent'lara `git stash` / `git checkout --` / `git reset` yasaklayın.** Aynı ağaçta
  çalışırken birbirlerinin işini siliyorlar.
- **`role="status"` çakışması:** sidebar'ın yükleniyor iskeleti `role="status"` taşıyor;
  sayfa seviyesindeki `getByRole("status")` sorguları onunla yarışıyor. E2E'de `main`'e
  daraltın.
- **`pnpm build` çalışırken dev sunucu açıksa** `.next` ezilir ve sayfalar 500 döner.
  `rm -rf .next` + yeniden başlatma çözer.
